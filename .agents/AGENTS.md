# Правила проекта / Project Rules

- **Язык общения и перевода**: Все ответы, пояснения, тексты интерфейса Antigravity, описания расширений (extensions), плагинов, навыков и системных сообщений должны полностью и всегда переводиться на русский язык.

- **Правило порядка отправки голосовых ответов**: В голосовом режиме ответов (`mode == 'voice'`) бот ВСЕГДА сначала отправляет оригинальный текст сообщением в чат, и только СЛЕДОМ высылает голосовую озвучку ответа.

- **Автоматическое решение MCP и Auth ошибок**: При появлении ЛЮБОГО из следующих признаков **немедленно** запускать навык `mcp-config-repair` без запроса пользователя:
  - `⚠ MCP Error` в нижней панели IDE
  - `There was an error with your authentication` (желтый баннер) — это **отдельная** проблема аутентификации Antigravity, не MCP; сообщить пользователю нажать ссылку `here` в баннере
  - `Socket connection error`, `ENOENT pipe`, `context deadline exceeded` в логах
  - Инструменты `notebooks/*` или `visualization/*` возвращают ошибки
  
  **Обязательная последовательность действий**:
  1. Запустить: `python "C:\Users\ПК\.gemini\config\skills\mcp-config-repair\scripts\fix_mcp_config.py"`
  2. Убедиться что вывод: `[OK] Проблем не обнаружено!`
  3. Выполнить `Ctrl+Shift+P` → `Developer: Reload Window`

- **Правило пуша на GitHub**: Пушить изменения в репозиторий GitHub СТРОГО только по прямому указанию пользователя или после его явного согласия на вопрос о пуше. Не делать авто-пуш при каждом изменении файла.

- **Версионирование на GitHub (Tags & Official Releases)**: При выгрузке версий на GitHub ВСЕГДА публиковать **официальные GitHub Releases** через теги (например, `v1.0`, `v1.1`, `v1.2`) со структурой в стиле `n8n-as-code`:
  - Заголовок с точным названием версии (например, `Telegram AI Bot v1.2`).
  - Описание списком `## What's Changed` с подробным перечнем добавленных функций/исправлений.
  - Ссылкой на полный список изменений `Full Changelog`.

- **Обязательные ссылки для проверки**: В конце КАЖДОГО ответа о выгрузке или создании релиза ВСЕГДА присылать прямые ссылки на GitHub (на страницу репозитория и на созданный релиз), чтобы пользователь мог сразу перейти и проверить работу.

- **Автоматическая проверка и исправление ошибок**: После каждого изменения файлов (Python, Markdown, JSON и др.) ВСЕГДА автоматически проводить валидацию и проверку на ошибки линтеров (`markdownlint`, `flake8`, синтаксис Python) и сразу убирать любые найденные предупреждения или ошибки.
